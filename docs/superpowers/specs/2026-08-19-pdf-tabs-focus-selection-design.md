# PDF 多标签、选区与专注阅读设计

## 背景与目标

现有 PDF 阅读模式一次只持有一个文档，原始鼠标坐标必须落在 PDF 文字范围内才能形成选区，窗口快捷键和显示状态也不符合最新阅读习惯。本次改造需要在不影响便捷模式、翻译协议、缓存和标记存储的前提下完成：

- 同时打开多个 PDF，并通过顶部标签切换。
- 每个标签独立保留滚动、缩放、选区、译文和词组分析。
- 提高页内文字命中率，拖动时实时显示蓝色选区。
- `Alt+Q` 直接进入便捷模式。
- PDF 模式默认最大化，并提供可按 `Esc` 退出的专注阅读。

仍不加入 OCR、跨页选区、批量翻译、笔记系统或无限制预加载。功能继续保留在本地 `feature/pdf-reader` 分支，验收前不打包、不推送。

## 总体架构

`PdfReaderWindow` 从“单文档工作区”改为“多文档容器”。它只负责全局工具栏、标签管理、空白引导、窗口状态和专注模式。每个标签是独立的 `PdfReaderTab`，负责一个完整阅读会话：

```text
PdfReaderWindow
├── global toolbar
├── QTabWidget
│   ├── PdfReaderTab A
│   │   ├── SelectablePdfView A
│   │   ├── translation panel A
│   │   └── PdfTranslationController A
│   └── PdfReaderTab B
│       ├── SelectablePdfView B
│       ├── translation panel B
│       └── PdfTranslationController B
└── empty-state page
```

所有标签共享 `SettingsStore`、`LearningRepository` 和一个 `QtPdfTranslationClient`。客户端已经按请求 ID 管理并发请求；各标签控制器只接收自己的请求结果。关闭标签时控制器取消对应请求，Qt 会在接收者销毁后断开信号连接。

该边界使每个标签的状态天然独立，避免在切换标签时手工序列化和恢复大量控件状态，也防止后台流式结果写入当前标签。

## 多 PDF 标签行为

### 打开与切换

- “打开 PDF”允许连续选择文件；每个成功加载的文件创建一个标签。
- 标签标题使用文件名，工具提示显示规范化绝对路径。
- 规范化后的路径使用大小写不敏感比较；重复打开时切换到已有标签。
- 文件无效、损坏或需要密码时，不保留失败标签，并在窗口状态区显示错误。
- 不设置固定标签数量。`QPdfView` 继续按 Qt 的方式按需渲染，应用不主动预渲染所有页面。

### 标签状态

每个 `PdfReaderTab` 独立持有：

- `QPdfDocument`、文档指纹和标记列表；
- 当前滚动位置、页码、缩放模式和缩放比例；
- 当前最终选区和拖动中的预览选区；
- 原文、流式译文、词组分析、状态提示；
- 当前翻译请求 ID、缓存键和性能指标上下文。

切换标签不取消请求。后台标签可以继续完成翻译，但只更新自身面板。关闭标签会取消其活动请求、关闭 PDF 文档并释放标签控件；SQLite 中的标记与缓存不会删除。

### 空白状态

关闭最后一个标签后，窗口保留并显示简洁的“打开 PDF”引导页。重新打开文件后自动切换到标签区域。

## 文字命中与实时选区

### 根因

`QPdfDocument.getSelection(page, start, end)` 在起点或终点落于文字包围区域之外时可能返回无效结果。现有实现直接传入鼠标坐标且只在释放时提取选区，因此行首、行尾空白和文字附近难以选择，也没有拖动反馈。

### 文字命中缓存

`SelectablePdfView` 为每页惰性缓存 `getAllText(page).bounds()` 产生的文字区域。加载或关闭文档时清空缓存。鼠标移动只查询当前页缓存，不重复解析整页。

命中规则：

- 鼠标位于文字区域内，或距离最近文字区域不超过 10 个 PDF 点时，视为可选文字并显示 `Qt.IBeamCursor`；
- 远离文字时恢复普通箭头；
- 没有文字层的页面保持普通箭头。

### 吸附与选择

选择先使用原始起止点调用 Qt。若无效，则分别查找最近文字区域，将坐标限制到区域内部后重试。超过命中距离的起点不开始文字选择；拖动终点允许吸附到同行或其他文字行，从而支持正常的多行页内选择。

鼠标拖动时生成临时 `PdfTextSelection` 并立即重绘蓝色覆盖层，但不发出业务层 `selection_changed`。鼠标释放后才发出一次最终选区；无有效文字时发出 `None`。这样既有即时视觉反馈，也不会在每个鼠标事件中取消和重启翻译状态。

选择继续限制在同一 PDF 页面。扫描 PDF 没有文字层时，状态区提示“当前页面没有可选择文字”。

## 翻译、标记与快捷键

每个标签创建自己的 `PdfTranslationController`，但注入同一个并发安全的 `QtPdfTranslationClient`。控制器继续使用请求 ID 忽略不属于自己的结果，并沿用现有缓存、指标和标记仓储。

`Alt+W` 只检查当前可见 PDF 标签：

1. 当前标签有最终选区时，翻译该选区；
2. 当前标签没有选区、PDF 窗口不可见或没有标签时，回退到原系统划线翻译。

添加、删除标记只作用于当前标签的文档和选区。主题设置仍是全局偏好，切换后同步应用到所有已打开标签；各标签的缩放和滚动状态保持独立。

`Alt+Q` 不再打开模式选择器，而是直接创建或显示便捷模式窗口。应用冷启动仍显示模式选择器，托盘仍可显式进入任一模式。

## 窗口与专注阅读

普通 PDF 模式首次显示和从专注模式恢复时调用最大化显示，保留 Windows 标题栏和任务栏。

全局工具栏新增“专注阅读”按钮。进入专注模式时：

- 保存进入前的窗口状态；
- 隐藏全局工具栏和标签栏；
- 使用系统全屏显示；
- 只保留当前 `PdfReaderTab` 的 PDF 与译文分栏。

专注模式不重建标签，不清空选区、译文、词组、缩放或滚动位置。`Esc` 仅在专注模式下被窗口拦截，退出全屏、恢复工具栏和标签栏，并回到最大化 PDF 窗口。普通模式下 `Esc` 不改变窗口。

若当前没有 PDF，专注阅读按钮禁用。专注模式期间仍可使用 `Alt+W`、缩放、标记和译文面板内的操作；由于全局工具栏隐藏，退出后才能切换标签或打开新文件。

## 错误与资源处理

- 失败加载不进入标签集合。
- 重复文件只聚焦，不增加文档和网络资源。
- 标签关闭先取消活动请求，再关闭 `QPdfDocument`，最后移除控件。
- 后台标签失败只更新自身状态，不弹出抢焦点对话框。
- 关闭当前标签后选择相邻标签；没有标签时清空应用层活动 PDF 选区。
- 退出应用时依次关闭所有标签、取消共享客户端中的剩余请求，再关闭现有服务。

## 测试策略

### 选区与光标

- 从行首、行尾附近空白开始拖动可以吸附并选中文字；
- 远离文字不产生选区；
- 靠近文字时为 I 形光标，离开后恢复箭头；
- 拖动过程中已有蓝色预览，释放前不通知控制器；
- 释放时只提交一次最终选区；
- 缩放和高 DPI 下文字区域、选区和标记继续对齐。

### 多标签

- 打开两个真实 PDF 会创建两个标签；
- 重复打开同一路径只聚焦原标签；
- 每个标签保留自己的滚动、缩放、选区、译文和词组；
- 后台请求结果不修改当前标签；
- 关闭标签取消对应请求但不影响其他标签；
- 最后一个标签关闭后显示空白引导。

### 模式与窗口

- 冷启动仍只显示模式选择器；
- `Alt+Q` 直接显示便捷模式；
- PDF 模式默认最大化；
- 专注阅读隐藏工具栏和标签栏；
- `Esc` 恢复最大化与原有阅读状态；
- 没有标签时无法进入专注阅读；
- `Alt+W` 始终路由到当前标签，缺少选区时正确回退。

最终执行 PDF 聚焦测试、完整测试套件、Python 编译检查、冷启动烟测和真实双文档切换烟测。验收前不运行打包脚本，也不推送该功能分支。
